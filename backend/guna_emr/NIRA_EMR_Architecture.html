1. System Overview

NIRA EMR is a Universal Data → FHIR EMR Converter that accepts any healthcare input — bookings, symptom interviews, doctor notes, vitals, or unstructured text — and converts them into standardized FHIR R4 resources stored in a HAPI FHIR server.

Goal: Patient uploads symptoms/booking/history → AI Agent → Structured FHIR EMR → Doctor Queue

Key Capabilities

🔄 Universal Input
Handles bookings, symptom text, doctor notes, vitals, and any unstructured healthcare data through a single endpoint.
🧠 NLP Extraction
Regex-based engine extracts symptoms, vitals (BP, HR, temp, SpO2), diagnoses, medications, and exam findings.
🔥 FHIR R4 Compliant
All data stored as standard FHIR R4 resources: Patient, Encounter, Observation, Condition, Composition, MedicationRequest.
⚡ Realtime Queue
OPD queue with token system, Socket.IO notifications, and doctor portal updates in real-time.

5. API Reference

Universal Converter

MethodEndpointInputOutput
POST/api/convertAny JSON or textAuto-detected → FHIR resources
POST/api/convert/booking{phone, time, doctor}Patient + Encounter(planned)
POST/api/convert/symptoms{text, patientPhone?}Patient + Encounter + Obs + Composition
POST/api/convert/doctor-notes{text, patientId, doctorName}Composition + Condition + MedicationReq
POST/api/convert/vitals{patientId, systolic, ...}Observation resources

Queue Management

MethodEndpointPurpose
GET/api/queueFull OPD queue
GET/api/queue/doctor/:nameQueue filtered by doctor
PATCH/api/queue/:id/statusUpdate: waiting → in-progress → completed

FHIR Proxy

MethodEndpointPurpose

GET/api/fhir/patient/:id/everythingAll resources for a patient
GET/api/fhir/encounter/:idGet encounter
GET/api/fhir/search/:resourceTypeSearch any FHIR resource type

7. NLP Entity Extraction

The NLP extractor uses regex patterns to extract medical entities from unstructured text:

Entity TypePatterns RecognizedExample
Blood PressureBP 140/90, blood pressure 130/85→ systolic: 140, diastolic: 90
Heart RateHR 72, pulse 80 bpm→ heartRate: 72
Temperaturetemp 101, fever 102°F→ temperature: 101
SpO2spo2 98%, oxygen sat 95%→ spo2: 98
Weightweight 70 kg, wt 65→ weight: 70
Respiratory RateRR 18, resp rate 20/min→ respiratoryRate: 18
Symptoms40+ keywords: fever, cough, headache, etc.→ ["fever", "cough"]
Durationfor 3 days, since 2 weeks→ "3 days"
DiagnosesDx viral URTI, inline keywords→ ["viral URTI"]
MedicationsRx paracetamol, Tab amoxicillin→ ["paracetamol"]
Exam FindingsExam normal, O/E: chest clear→ ["Normal examination"]

8. Deployment

Docker Compose (Production)

cd guna_emr
cp .env.example .env       # Set POSTGRES_PASSWORD
docker-compose up -d       # Starts all 7 services

Services start in dependency order:

PostgreSQL
→
HAPI FHIR + Redis + OpenMRS
→
Converter Agent
→
Patient & Doctor Portals

Dev Mode (Local — no Docker)

# Terminal 1 — API Backend
cd guna_emr/converter-agent && npm install && npm run dev

# Terminal 2 — Patient Portal
cd guna_emr/patient-portal && npm install && npm run dev

# Terminal 3 — Doctor Portal
cd guna_emr/doctor-portal && npm install && npm run dev
Graceful Degradation: The converter agent runs without PostgreSQL, Redis, or HAPI FHIR — using in-memory storage. All features work for development and testing.
